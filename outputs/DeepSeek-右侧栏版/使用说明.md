# Runa学习助手 1.14.0

主界面只保留学习内容、测验处理、后续动作。播放设置和运行记录默认折叠，开始/暂停只显示当前可用的一项；跳过按钮只在当前测验需要处理时出现。已删除重复的“视频助手/解题助手”和分散的功能复选框。

## 更新

1. 暂停旧助手，用新版覆盖原加载文件夹，在 Edge 扩展管理页重新加载。
2. 刷新整个课程标签页，重新打开侧栏。仅收起再打开不足以更新课程页脚本。
3. 确认标题为 Runa学习助手、下面显示 v1.14.0，再选择学习方式并开始。同一路径更新可保留本机 Key。

首次安装：解压，在 edge://extensions 开启开发人员模式，加载包含 manifest.json 的 DeepSeek-右侧栏版 文件夹。单击银白发人物图标打开右侧栏，Alt+Q 和右键搜题也可以打开。文件夹保留原名以方便已有安装原路径更新；显示名称统一为 Runa学习助手。请保留加载文件夹。

## 三个选择怎么用

**学习内容：**视频 + 章节测验、只看视频（跳过测验）、只做章节测验。只看视频时隐藏测验处理；只做测验时隐藏播放设置。

**测验处理：**提交答案、暂存答案、仅填写并等待检查。这里不再同时定义是否继续。

**后续动作：**继续下一项或下一节、留在本节。提交或暂存成功才执行后续动作；“视频 + 测验”会先完成本节的视频和测验，再决定是否进入下一节。只看视频并选择停留，则在当前视频结束后停下。

选择“仅填写，等我检查”时，继续选项明确显示“我保存或提交后继续”。填写后先停下，收到你手动保存/提交成功的结果才继续。选择“留在本节”，手动保存或提交也不会自动接续。

选择“暂存答案 + 留在本节”，等价于以前的“答完暂存，留在本节”，自动推进和手动成功接续均关闭。后台也会纠正旧版传入的互斥参数，不能再同时启用“暂存停留”和“自动继续”。

## 播放设置与临时操作

展开“播放设置”可选视频弹题处理方式（AI 解答并提交、AI 填写后由你提交、手动处理）、速度和静音。视频中的弹题与章节测验分别处理。

“跳过本次测验并继续”只影响当前测验，不保存、不提交，也不把测验标为完成。提交请求已发出时，该按钮禁用。选择只看视频后不重复显示这项操作。

运行记录默认折叠；需要检查失败原因时展开查看。明确点击暂停后，手动保存不会恢复运行。收起侧栏保留任务；关闭课程标签或退出浏览器会停止运行，同时保留已写入的本地进度。重新打开同一课程后点击“继续上次进度”，恢复章节与任务位置，并重新读取平台状态。只有已存在的进度能恢复，不能补回旧版关闭前未持久保存的状态。

## 补做测验

暂停后，在目录选择想补做的起始章节，选择“视频 + 章节测验”或“只做章节测验”，再选择提交/暂存方式并开始。每次启动重新读取测验，旧的跳过记录不跨运行生效。已有草稿保留，确认已提交的测验不会重复提交；目录里的 √ 不作为测验提交证据。

识别章节目录后，从选定章节向后处理，末尾再检查本轮未访问的前面章节；每轮目录最多遍历一次。锁定章节不强行进入；目录结构无法识别时仍使用下一节按钮，不能保证回查前面的章节。AI 分歧题会在本轮遍历结束后自动返回一次。跳过的视频或只暂存的测验仍可能未完成，目录检查结束不等于全部课程完成。选择留在本节时不进行目录回扫。

## 多视频与答题复核

1.13.0 在播放课程内容时也处理可识别的 PPT 原生翻页。带音频的课件先播完当前页音频；每次翻页后确认页码变化，最终等待平台给出课件完成状态。普通 ReadWeb 书籍使用平台阅读器入口；计时阅读依照页面 timing 等候、逐项切换原生页码后确认，链接任务点击原生链接一次。三类任务都等待平台确认，不把点击或等待当作完成；未识别阅读器进入待处理队列。

阅读理解和完形填空的已识别小题分别答题，公共材料保留在各题中。文字与填空题支持同源富文本编辑 iframe、UEditor 和多个输入框；已有人工答案保留。连线题逐行映射并核对原生字段；图片题读取当前题干/选项图片送视觉模型，跨域图片转换为字节，不发送带签名的图片网址。字体采用旧表与 OCS 位图匹配，低置信字形和未适配结构进入待处理队列，不阻挡其他可处理题目。选择仅填写/留在本节时仍停留等待检查。

同页多个视频或音频按页面顺序处理，包括嵌套框架、延迟创建播放器和没有任务点图标的媒体。隐藏旧框架不处理，已完成的任务不重播；当前媒体播放结束后再接续下一段，不因目录提前打勾而截断当前视频。等待加载从当前播放器启动计时。

1.10.0 加入平台附件任务 ID 匹配。相同任务的重复播放器去重；相同视频内容的不同任务分别处理。附件显示还有媒体、播放器尚未出现时会等待，不提前离开本页。数据不完整时沿用已有页面识别；任务匹配有冲突时不猜测完成状态。播放器或模型请求失败会有限恢复；仍失败的媒体/阅读任务进入队列，启用继续时先处理其他任务，目录末尾回访一次。仍无法确认的项目保留为待处理，不宣称完成。选择留在本节仍会停留。

“当前页面任务”默认折叠，分别列出视频播放结束、平台任务点已完成、测验暂存和测验提交。视频完成与测验提交独立，目录 √ 或附件已通过不能让未提交测验被跳过。播放器框架刷新时重新扫描；保存或提交已发出时保留结果等待，不盲目重复请求。进度恢复时不会沿用此清单的旧文档目标，会重新识别媒体和题目。

## 答题记录与恢复

“答题记录”默认折叠，保留最近 200 道题的题干、选项、AI 采用答案、页面选中项、理由、模型判断及暂存/提交/跳过结果。每题最多保留两轮判断，每轮各自保存当时的选项顺序；长内容有截取上限。点击“导出记录”下载 JSON，便于核对丢分原因。它不是题库，历史结论不自动当作新题答案。

恢复进度会保留上次学习方式和检查/提交选择。上次暂存或提交没有确认结果时，先核对平台状态，不能自动重发同一个未知结果的请求；如页面没有成功证据，会明确提示手动核对。恢复到章节任务位置，不伪造视频已观看时长，也不会强行拖动平台禁止拖动的视频。本地存储写入失败时会提示，请在关闭前导出重要答题记录。

本版源码已迁移为 TypeScript，加载包仍为浏览器可直接运行的 JavaScript，无需安装 Node 或额外后台服务。源码、构建与检查说明位于工作目录的 README.md；不要直接修改自动生成的 JS。

客观题从两个角度各独立判断两次。四次答案一致就填写；有分歧、格式冲突或请求失败时，各追加一次关键条件复核。追加的两次必须结论一致且明确完成核对，才能填写，不按简单多数强行选择。判断题先得到布尔值对错，再匹配页面实际“对/错”选项，避免默认 A 就是对；题干时间、地点和否定词必须完整检查。

1.14.0 默认复核跟随主模型，默认是 deepseek-flash + deepseek-flash，不再因复核留空而自动调用 Pro。“设置 → 答题复核模型”可以留空或选择 deepseek-flash；明确填写 deepseek-v4-pro 才采用 Pro 复核。已有明确填写的模型设置保留，不擅自覆盖。自定义兼容接口也支持指定任意有效模型名称，两个模型沿用当前接口和 Key。每轮每题通常 4 次、分歧时 6 次请求；待处理题最多自动回访一次，可能再产生一轮费用。

官方目前仅 Flash 支持图片，图片题四次判断使用同一视觉模型。文字题的 Flash + Flash 也是同一模型不同角度采样，记录会明确标明，不能视为两个独立模型；四次一致仍可能答错。模型名称不同也不能证明错误互相独立。

讨论、简答和心得的共享提示词要求自然简洁的学生表达、普通中文段落，避免 Markdown 标题、星号加粗、反引号代码围栏、装饰分隔线、emoji、箭头、花式符号与重复套话；不编造个人经历或引用。数学、代码和题目明确要求的格式保留。讨论草稿另做标记与装饰字符清理、字数检查；不能保证主观文字风格或事实完全正确。

## 课程讨论

“课程助手 → 讨论设置 → 教师话题”可选择“不处理讨论”“生成草稿，留待检查”“自动回复教师话题”，默认关闭。本节视频/测验任务处理后、离开章节前处理已加载的讨论列表；不会因为开启讨论而跳过未完成测验。草稿在“讨论记录与草稿”中查看和复制，不向平台发布。选择自动回复时，在后台打开原生话题页，填写唯一的回复框、点击原生回复按钮，并核对新增回复与输入框清空后才记录成功。

仅适配已核对的章节右栏 itemDiscuss 和 groupweb /course/topic/v3/bbs/.../replysList 页面，且话题作者明确标为“老师”。不新建话题、不复制其他同学回复。已有个人回复或手工草稿保留；课程、班级、学生身份与章节变化时不继续发布。讨论仅用当前主模型生成一次；已有草稿改为自动回复时复用草稿。

发布前先持久保存状态。重启、超时或结果不明时不自动重发，记录显示“发布结果待核对”；讨论失败不会阻挡其他章节。只适配已识别的数字字数要求、文字话题；图片、附件、未知页面及特殊要求留待检查。已记录的失败不自动无限重试。讨论完成不等于平台课程积分已到账，仍以平台记录为准。

每道客观题初次处理调用 4 次，追加复核后最多 6 次。未解决的题返回重试一次，最多再调用 6 次；确定并已保存的答案不重复询问。调用费与等待时间会增加。HTTP 连接、429 与指定 5xx 每次请求最多追加两次有限重试；无效 Key 不重试。手动搜题和填空/文字题未采用四票流程。

选择“提交/暂存 + 继续”时，未解决的题加入待核对队列，原生暂存确定答案，收到保存成功结果后继续其他任务。到达目录末尾后自动回访这些题一次；仍无一致结论则保留待核对记录，不无限调用，也不提交含未解决题的章节测验。平台判错或要求回看的视频弹题同样排队回访，其他可处理视频与章节继续；受阻视频保持未完成状态，不反复提交同一错误答案。选择“留在本节”或“仅填写并等待检查”仍遵从你指定的停留方式。

“待核对题”只在有记录时出现，默认折叠，展开可看题干与原因。队列随本地进度保存，退出浏览器后点击继续并重新读取课程状态。四次一致无法保证事实正确；研究与限制见 改进依据.md。

## 接口与支持范围

AI 功能在“设置”填写自己的 Key。默认接口 https://api.deepseek.com，模型 deepseek-flash。测试连接会调用真实接口并使用额度。不要同时运行原搜题酱的课程助手。

支持普通单选、多选、判断、多个填空、同源富文本、两种已适配连线布局、图片及阅读/完形小题，以及上述教师文字话题讨论。AI 分歧、不可读图片/字体、未知结构或无法识别的对错选项进入待处理队列；未知结果的保存/提交仍需检查，不盲目重发。考试页不自动填写或提交；跨域自定义编辑器、直播、其他讨论布局、其他平台及原站会员题库未实现。PPT、ReadWeb、计时阅读使用已核对的原生结构，不能代表全部 PDF/阅读器。具体剩余差距见“开发差距与验收.md”。

播放器通过页面原生按钮与媒体 API 启动；下一节加载时等待新文档。平台禁止离开或最小化时，需要保持课程页可见；收起侧栏不代表平台允许后台计时。助手不伪造观看时间、可见状态或完成标记。

## 本机数据与验证

Key 保存在本机扩展 storage.local，不回显、不同步，并限制内容脚本访问。题目只在主动提问、测试连接或开启 AI 处理时发送到你配置的接口。保存/提交结果观察器只保留最小成功标志，不复制 Cookie、Token、请求体或响应 URL。发布包无 Key、用户资料及测试浏览器配置。

本版检查覆盖多媒体排序与动态识别、语义答案映射、四票及分歧复核、部分暂存后继续、自动回访、拒绝题不循环提交、第二模型设置与待核对列表，并保留保存/提交、补做、切换与播放器回归。全部使用隔离浏览器和自建模拟平台，未代用户在真实课程提交、未测量真实模型正确率或最终记分，详情见 验证记录.md。

开发检查：node check.cjs。使用扩展不需要 Node.js。字体来源见 第三方来源.md；这是独立本地助手，不是大学搜题酱官方版本。旧包保留在工作目录归档中，Edge 中旧安装项需自行移除。
